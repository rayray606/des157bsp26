Feasibility Report

Project Overview

My capstone project will explore the mental health experiences of Korean pastor's kids and how church culture, family expectations, and mental health stigma can shape their emotional well-being. The project will be an interactive web experience that allows users to explore current realities, possible dystopian futures, and more hopeful futures for Korean church communities.

Planned Features

  • Interactive homepage: Introduces the topic and main question of the project.
  • Scroll-based storytelling: Users move through different sections about pressure, identity, mental health, and future possibilities.
  • Future scenario sections: The site will compare a future where mental health remains hidden with a future where churches provide more support.
  • Data visualization: Charts will show research findings or survey responses related to mental health stigma and support.
  • Animated background: Gradients may shift to reflect emotional tone, such as stress, silence, hope, or healing.
  • Reflection questions: Users may answer prompts about what kind of future they want faith communities to create.
  • Responsive design: The project will work on both desktop and mobile screens.

Technologies and Libraries

  • HTML: Used to structure the website content and sections.
  • CSS: Used for layout, typography, colors, spacing, and responsive design.
  • JavaScript: Used for interactivity, buttons, user choices, and changing content.
  • AOS Library: Used for scroll animations as users move through the story.
  • Chart.js: Used to create simple charts and data visualizations.
  • Granim.js: Used to create animated gradient backgrounds that support the emotional tone of the project.
  • D3.js: Considered for advanced data visualization, but may be too complex for the project timeline.

Skill Assessment

I feel comfortable using HTML and CSS because these are skills I have practiced throughout DES 157B. I have some experience with JavaScript, but I will need to keep the interactions simple and manageable. AOS seems realistic because it only requires adding simple attributes to HTML elements. Chart.js also seems manageable because it provides ready-made chart types. Granim.js may be new to me, but it appears simple enough to learn within the project timeline. D3.js is the most difficult library, so I may not use it unless I have extra time.

Feasibility Assessment

This project is feasible if I keep the scope focused on a single-page interactive storytelling website. The most important parts of the project will be research, writing, design, and creating a clear user experience. The coding is manageable as long as I use simple JavaScript interactions and avoid building a complicated app with a database or user accounts.

Possible Difficulties

  • Research difficulty: It may be hard to find sources specifically about Korean pastor's kids, so I may need to combine research about Korean churches, mental health stigma, and pastor families.
  • Sensitive content: I need to be careful not to make broad generalizations about all Korean churches or all pastor's kids.
  • Data collection: If I cannot collect enough original survey responses, I can use existing research data instead.
  • Coding scope: D3.js may be too advanced, so I will prioritize Chart.js for charts.

Scope Changes Since Proposal

Since the original proposal, I have decided to keep the project more focused and realistic. Instead of creating many different branching story paths, I will focus on three main sections: current reality, a future without change, and a future with support. This will make the project easier to design and code while still allowing users to reflect on possible futures.
